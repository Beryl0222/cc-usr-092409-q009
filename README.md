# 医者荣誉贡献档案

本仓库保存该服务的领域资料与最小事件约定，供业务团队在统一语义上继续建设。

## 已有内容

- `contracts/domain.schema.json`：领域事件的基础字段、聚合类型和事件名称。
- `data/sample.json`：可用于联调的中文样例记录。
- `src/validator.js`：只负责校验基础事件信封，不包含业务流程。
- `src/service.js`：贡献与公开叙事档案服务（命令、归约、查询）。
- `src/eventLog.js`：追加式事件日志，JSONL 落盘，重启后按序重放。
- `src/fingerprint.js`：内容指纹（稳定序列化 + SHA-256），用于归并重复件。
- `tests/`：验证样例、基础约定与各领域流程。

## 领域边界

当前资料围绕团队贡献、资质核验和患者同意整理。事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正应产生后继记录。涉及个人、机构或商业敏感信息时，调用方只读取完成职责所必需的字段。

## 领域流程

### 贡献声明 → 确认 → 裁定

1. `submitStatement`：登记贡献声明，绑定时间区间、职责、证据摘要与共同参与者。
2. `confirmStatement`：须由当事人本人确认；离线确认按指纹归并，重复件只留痕。
3. `suggestAggregation`：按共同参与者、工作时段与成果线索自动聚合，**只给出建议**，不改动归属。
4. `adjudicate`：独立审核人（不得为当事人或共同参与者）裁定归属；`expectedVersion` 提供乐观并发控制，并发裁定只有先到者生效。

同一成果允许多人按不同角色获得说明；`achievementCount()` 对同一成果只计一次，相同人员相同角色拒绝重复计入。

### 同意 → 发布 → 撤回

- `grantConsent`：按用途 × 渠道 × 有效期限定范围，并登记获准公开的摘要（最小披露）。
- `releaseStory`：仅当存在覆盖该用途与渠道且在有效期内的同意时才可发布；发布版本只保存获准摘要。
- `withdrawConsent`：可整体或部分撤回。撤回只阻止撤回范围内的新发布；已发布版本保持原样并追加处置标注；同时生成待送达宣传部门的撤回通知，指明哪些版本必须停止使用。`pendingNotifications()` 在重启后仍然可用。

### 异议 → 归属更正

- `fileObjection` / `resolveObjection`：异议须设定期限；成立时须给出更正后的归属说明，生成 `ATTRIBUTION_CORRECTED` 后继记录。
- 历史提名、投票与公开版本保持原样；`internalAchievementView` 返回当前有效结论与校正理由。

### 迟到证明与冲突复核

- `attachProof`：重复证明按指纹归并（保留来源）；与已登记证据摘要冲突时声明进入 `pending_review`，已计入成果的说明被挂起，待独立审核人复核后恢复。

### 查询视图

- 内部：`internalStatementView` / `internalAchievementView` / `internalConsentChain` 还原团队贡献、同意链与校正理由。
- 公众：`publicStoryView` 只返回获准摘要与处置标注。

## 本地检查

```bash
node --test
```

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

上述命令均在单个 Linux 应用容器内执行，不需要另行启动外部服务。

测试覆盖：共同贡献（多人多角色计为一项成果）、迟到证明（归并、冲突挂起与复核恢复）、部分撤回（范围外发布不受影响、已发布版本追加处置）、并发裁定（版本冲突拒绝）、异议更正（历史不变、当前结论生效）与重启恢复（撤回通知与异议期限续办）。
